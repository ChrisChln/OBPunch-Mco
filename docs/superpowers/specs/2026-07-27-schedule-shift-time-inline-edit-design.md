# 排班班次时间行内编辑设计

## 目标

在后台排班表中增加“班次时间 / Shift Time”列，让有权限的用户点击时间后直接行内编辑。排班页与员工信息页共同读写 `ob_employees.shift_time`，不创建重复字段或排班级时间副本。

## 范围

- 在排班表“班次”列右侧增加“班次时间”列。
- 显示员工记录中的 `shift_time`，规范化为 `HH:MM`；空值显示 `-`。
- 点击时间进入行内时间输入。
- Enter 或失焦保存，Esc 取消并恢复原值。
- 保存期间提供明确的加载和禁用状态。
- 成功后同步当前页面的员工状态，并写入员工变更审计。
- 失败时保留编辑状态与输入值，并显示错误信息。

不包含：

- 新增数据库字段或迁移。
- 为每天的排班记录保存不同的班次时间。
- 批量编辑班次时间。
- 修改员工的早班/晚班类型。

## 数据模型与数据流

唯一数据源为 `ob_employees.shift_time`。

1. 排班表从现有 `employees` 集合读取员工的 `shift_time` 或兼容字段 `ShiftTime`。
2. 展示前使用现有 `normalizeShiftTimeValue` 规范化时间。
3. 用户保存后，只更新 `ob_employees.shift_time`。
4. 写入成功后更新本地 `employees` 集合，因此排班表立即显示新值；员工信息页下次渲染或刷新时读取相同字段。
5. 审计记录包含员工工号、变更前后时间及 `source: "schedule"`。

## 交互设计

- 新列位于“班次 / Shift”与 `UPH` 之间。
- 非编辑状态显示 `HH:MM`；无有效值时显示 `-`。
- 可编辑单元格使用按钮语义，并提供“编辑班次时间 / Edit shift time”的可访问名称。
- 点击后原位显示 `input[type="time"]` 并自动聚焦、选中当前值。
- Enter 保存；失焦保存；Esc 取消。
- 同一时间只编辑一名员工。
- 保存期间输入框禁用，并显示保存状态，避免重复提交。
- 输入未变化时直接退出编辑，不发送数据库请求。

## 权限

班次时间编辑必须同时满足：

- 排班模块具备操作权限。
- 用户具备该员工岗位的排班操作权限。
- 当前页面没有全局锁定。

不满足权限时仅显示时间，不提供可编辑交互。

## 校验与错误处理

- 保存前使用现有时间规范化函数校验。
- 有效值以 `HH:MM` 写入数据库。
- 空值不通过时间输入产生；本功能不提供清空操作。
- 无效值不请求数据库，并显示双语错误信息。
- Supabase 未配置或更新失败时保留输入与编辑状态，显示明确错误。
- 成功后退出编辑并显示成功状态。

## 代码结构

- 在 `AdminAppPage.tsx` 中增加最小的编辑状态与保存协调逻辑，沿用现有排班 Label 行内更新模式。
- 将时间编辑的纯状态判断或输入解析提取为小型、可测试的 helper，避免把业务判断堆在 JSX 中。
- 保持员工查询和既有员工编辑表单不变，因为它们已经使用 `shift_time`。
- 仅对排班表列宽与对应表头、单元格做增量调整。

## 测试

采用测试先行：

- 纯逻辑测试：
  - 规范化有效班次时间。
  - 拒绝无效时间。
  - 相同值不触发保存。
  - Esc 恢复原值。
- 组件或页面测试：
  - 显示“班次时间”列和现有值。
  - 点击进入时间输入。
  - Enter 保存。
  - 失焦保存。
  - Esc 取消。
  - 只读或无岗位权限时不可编辑。
  - 保存中禁用，保存失败保留编辑状态。
- 验证：
  - 运行相关 Vitest。
  - 运行 `npm run build`。
  - 在排班页进行一次针对性的浏览器交互检查。

## 验收标准

- 排班表在“班次”后显示班次时间列。
- 时间值与员工信息中的班次时间完全同源。
- 点击时间可原位编辑，Enter/失焦保存，Esc 取消。
- 保存过程中有明确反馈，不产生重复请求。
- 权限、校验和失败场景均有明确行为。
- 相关测试和生产构建通过，桌面与窄屏不产生新的横向溢出问题。
