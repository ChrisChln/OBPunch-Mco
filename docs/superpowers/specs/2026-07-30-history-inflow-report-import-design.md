# 历史流入报表导入设计

## 目标

在 Forecast 的“历史流入”视图中增加“导入报表”入口。系统读取出库包裹报表，以“创建时间”确定日期和自然小时，以“货品数量”作为流入件数，自动生成每天 24 小时的历史流入数据。

该设计需要稳定处理单次约 100,000 行数据，同时保持页面可操作、提供确定的进度反馈，并避免部分覆盖或重复累计。

## 已确认规则

- 每行按照“创建时间”归入 `00:00–00:59` 至 `23:00–23:59` 的自然小时。
- 每个日期和小时的流入量为该范围内所有行“货品数量”的总和。
- 一个文件可包含多个日期，所有日期在一次导入中分别汇总。
- 文件中出现的日期覆盖 `volume_history` 中相同日期的完整 24 小时数据，不与旧值累计。
- 没有明细的小时写入 `0`。
- 整份文件先解析、校验和聚合；任何无效行都会阻止数据库写入。

## 示例文件验证

示例文件 `出库包裹报表_260730_003.xlsx` 的第一张工作表为 `Sheet1`，范围为 `A1:AL13220`，包含 13,219 条数据。

- 数量列：`货品数量`
- 时间列：`创建时间`
- 时间示例：`07/01/2026 05:18:00 PM`
- 有效日期：`2026-07-01`
- 文件货品数量合计：14,040
- 无效数量行：0
- 无效创建时间行：0

## 方案选择

采用浏览器端 Web Worker 解析和聚合。主线程只负责文件选择、状态展示和数据库写入。

与服务端上传原始文件相比，该方案不受服务端请求体大小和执行时限影响。十万行明细只在本地处理，数据库收到的是按日期聚合后的少量记录。

不采用在主线程直接解析的方案，因为大型 Excel 的解压、读取和逐行转换可能冻结页面。

## 架构

### 解析与聚合模块

新增独立、可测试的纯逻辑模块，负责：

1. 在第一张非空工作表中定位表头。
2. 对表头进行去首尾空格处理，精确识别“创建时间”和“货品数量”。
3. 解析 Excel 日期单元格、JavaScript `Date` 值和示例中的 AM/PM 文本。
4. 校验数量为有限、非负数；按现有 `volume_history` 整数约束要求，数量必须为整数。
5. 按本地业务日期和小时聚合，输出按日期排序的 `VolumeHistoryUploadRow[]`。
6. 为每个日期补齐 `h00` 至 `h23`，并将 `last_filled_hour` 设为当天最后出现有效数据的小时。

解析结果同时包含统计信息：读取行数、有效行数、日期数、总件数、最早日期和最晚日期。

### Web Worker

Worker 接收文件的 `ArrayBuffer`，使用现有 `xlsx` 依赖读取工作簿，并分批遍历工作表数据。每处理约 5,000 行发送一次进度消息。

Worker 消息采用明确的联合类型：

- `progress`：已处理行数、总行数和百分比。
- `success`：聚合结果和统计信息。
- `error`：用户可读错误、行号及字段名。

Worker 不访问 Supabase，也不改变 React 状态或数据库。

### 数据写入

页面收到完整成功结果后，复用现有 `upsertVolumeHistoryRows` 和写后校验逻辑，以 `date` 为冲突键覆盖保存。

为控制请求大小，聚合后的日期记录按固定小批次写入。只有 Worker 完成全部校验后才开始第一批写入。若数据库写入失败，页面显示失败原因，并刷新数据库数据以反映实际状态；不显示导入成功。

本功能不保存十万行包裹明细，也不新增数据库表或服务端 API。

## 界面与交互

- 在“历史流入”弹窗的历史视图内增加“导入报表”按钮，靠近现有日期和粘贴操作区。
- 接受 `.xlsx` 和 `.xls` 文件；该入口仅用于出库包裹报表，不接受历史流入模板 CSV。
- 选择文件后立即显示现有 BusyOverlay，并展示阶段：读取文件、解析百分比、保存、校验、刷新。
- 导入期间禁用重复导入、粘贴和保存操作。
- 成功提示采用简短摘要：`已导入 X 天 · Y 行 · Z 件`。
- 失败提示包含可执行信息，例如：`第 218 行“创建时间”无效`，且数据库保持未开始写入的状态。
- 页面完成后刷新历史流入表、趋势、自动预测快照和预测模型。
- 现有顶部模板导入和下载模板功能保持不变，避免改变已有工作流。

## 校验与错误处理

以下情况整份文件拒绝导入：

- 文件为空或没有非空工作表。
- 缺少“创建时间”或“货品数量”列。
- 创建时间为空、无法解析或超出有效日期范围。
- 货品数量为空、非数字、负数或非整数。
- 没有任何有效数据行。
- Worker 解析异常或内存不足。

重复表头以首次出现的目标列为准。空白尾行忽略；非空数据行不得静默跳过。

日期按用户浏览器的本地时间解释，避免把 `05:18 PM` 因 UTC 转换移动到其他日期或小时。

## 性能边界

- 验收目标：100,000 条数据可完成导入，解析期间主页面保持响应。
- Worker 分批报告进度，避免逐行消息造成额外开销。
- 只保留必要字段和按日期聚合结果，不构建十万条完整对象副本。
- 文件大小上限为 100 MB；超过上限时在读取前拒绝并提示。该上限覆盖示例结构下约十万行的目标规模，同时限制浏览器内存风险。
- 释放文件 ArrayBuffer、Worker 和文件输入引用，避免连续导入的内存累积。

## 测试策略

遵循 TDD，先看到测试因缺少功能而失败，再实现最小代码。

### 单元测试

- 同一小时多行数量正确累加。
- 跨小时生成正确的 `h00`–`h23`。
- 多日期分别生成记录并按日期排序。
- 无数据小时补 `0`。
- `last_filled_hour` 为最后出现数据的小时，即使该小时合计为 `0`。
- 支持 AM/PM 文本、Excel 日期值和 `Date` 值。
- 本地日期不受 UTC 时区偏移影响。
- 缺列、无效时间、空数量、负数、非整数均返回带行号错误。
- 10 万行合成数据聚合结果和统计信息正确。

### 页面测试

- 点击按钮打开专用文件选择器。
- 解析期间显示进度并禁用冲突操作。
- Worker 成功后才调用数据库 upsert。
- Worker 失败时不调用数据库。
- 成功提示包含天数、行数和总件数。
- 保存后触发现有历史和模型刷新。

### 验收验证

- 使用示例文件导入后，日期为 `2026-07-01`，全天 24 小时合计为 14,040。
- 重新导入同一文件不会翻倍，结果仍为 14,040。
- 运行目标 Vitest、完整构建，并在浏览器中验证历史流入弹窗和进度反馈。

## 非目标

- 不保存或展示包裹级明细。
- 不支持后台无人值守导入。
- 不新增服务端文件存储或导入任务队列。
- 不改变预测模型公式和 `volume_history` 表结构。
